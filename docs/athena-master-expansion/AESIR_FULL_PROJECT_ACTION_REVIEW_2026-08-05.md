## 3. First-principles mechanism analysis

A project this large fails if the representation layer is wrong.

The core mechanism should be:

```text
concepts → ontology → capability state → plugin routing → tasks → evidence → verification → memory/writeback
```

Project Athena should therefore prioritize control surfaces over more concept prose.

The required control surfaces are:

1. **Ontology:** what exists, what feeds what, and what depends on what.
2. **Capability state:** what is implemented, scaffolded, specified, conceptual, speculative, or blocked.
3. **Plugin action register:** which plugin should do which class of work.
4. **Governance exception log:** what was pushed to cloud and why it was allowed.
5. **Cycle report:** what happened in the work session, what evidence was used, and what comes next.

## 9. Hypothesis / architecture generation

### Path A — Documentation-first

Finish all specs first, then implement.

- Strength: maximum clarity.
- Weakness: can become endless writing.

### Path B — Runtime-first

Build local API/adapters now.

- Strength: creates working software quickly.
- Weakness: can encode messy architecture before ontology stabilizes.

### Path C — Control-layer first

Create ontology + capability matrix + plugin register, then build specs/runtime against those.

- Strength: balances clarity and execution.
- Weakness: requires discipline to maintain.

**Selected path:** Path C.
