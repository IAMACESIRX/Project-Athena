# Cross-Checking Truth Pipeline

## Pipeline

1. Claim is made.
2. Identify claim type.
3. Identify strongest available evidence.
4. Cross-check with at least one independent source where feasible.
5. Label confidence.
6. Record in memory only if useful.

## Cognition System Boundary

Outputs from `cognition/` are candidates until checked here.

Subtext, conceptual leaps, counter-intuitive discernment, non-linear disruption, original creation, and liquid-state readouts must be labeled before they influence core memory or runtime action.

## Claim Types

- file state,
- Git state,
- runtime state,
- user intent,
- policy,
- causality,
- future risk.

## Confidence Labels

- verified,
- likely,
- inferred,
- unverified,
- contradicted.

## Example

Claim: Docker is unavailable.

Evidence: `Invoke-LiveServerProbe.ps1` reports `docker command not found`.

Confidence: verified for current shell, not necessarily for entire machine.
