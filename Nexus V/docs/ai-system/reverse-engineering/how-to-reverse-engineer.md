# Reverse Engineering Protocol

Use this when learning how any project component works.

## Rules

- Observe before changing.
- Identify inputs, outputs, state, and dependencies.
- Build a small map.
- Record unknowns.
- Verify one claim at a time.
- Convert repeated discoveries into registries, module cards, or tools.

## Method

1. Name the target.
2. Identify owner layer and module.
3. Read source/config/docs.
4. Identify runtime signals.
5. Build interaction map.
6. Record assumptions.
7. Test with the least invasive probe.
8. Update project memory.

## Output

Reverse engineering work should produce at least one of:

- updated module card,
- updated dependency map,
- work item,
- diagnostic script,
- playbook,
- decision.
