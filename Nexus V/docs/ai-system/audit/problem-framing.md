# Problem Framing Architecture

Before solving, frame the problem.

## Frame Fields

- problem statement,
- affected layer,
- affected modules,
- current state,
- desired state,
- constraints,
- assumptions,
- evidence,
- risks,
- success criteria,
- rollback path.

## Failure To Frame

Symptoms:

- solving the wrong layer,
- over-editing,
- missing privacy risk,
- assuming runtime state,
- no verification path.

## Framing Output

For large work, create a work item or session handoff section using these fields.
