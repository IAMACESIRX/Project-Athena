# Project Athena Milestones

Updated: 2026-08-01

These milestones are the human-readable counterpart to `work/github-plan.json`.
They describe outcomes, not maturity claims. GitHub issues carry the executable
acceptance criteria.

## M0 - Source Reconciliation And Governance

Status: active

Outcome: Athena's recovered chats, media, decisions, and publication rules are
audited, scoped, and traceable before further architecture is promoted.

Exit criteria:

- official export reconciliation is complete or its absence remains explicit;
- raw and normalized source zones are separated from canonical memory;
- public-mirror policy and publication checks are active;
- all recovered storyboards are hashed, inventoried, and classified.

## M1 - Brain Stem And Continuity

Status: active

Outcome: a repeatable two-way chat/repository loop preserves context across
models and sessions without automatic canonical writeback.

Exit criteria:

- import normalizer supports audited JSONL and official ChatGPT exports;
- bounded and full repository context capsules are reproducible;
- promotion ledger and schemas are validated;
- repository integrity CI runs on every pull request and push.

## M2 - Distributed Cognitive Fabric

Status: planned

Outcome: models and tools dock through versioned Athena adapters and project
capsules while central Athena remains canonical.

Exit criteria:

- adapter and capsule contracts have conformance fixtures;
- a read-only Codex/local adapter passes a docking test;
- project capsule lineage, authority, and writeback rules are exercised;
- model and skill routing records evidence for every handoff.

## M3 - Evidence, Cognition, And Memory

Status: planned

Outcome: reasoning outputs retain evidence labels, contradictions, provenance,
and the correct memory-layer destination.

Exit criteria:

- claims bind to evidence IDs and uncertainty labels;
- cognition output labels are machine-readable and validated;
- semantic drift and non-monotonic revision produce auditable records;
- one full Athena task closes with verified memory writeback.

## M4 - Operative Duplex

Status: planned

Outcome: the independent operative AI model has bounded identity, observation,
action, safety, and recovery contracts with a read-only embodied proof slice.

Exit criteria:

- the system name and identity boundary are decided;
- Pilot/Witness separation is testable;
- the Cartographer can observe a desktop/application state without mutation;
- proposed actions carry authority, rollback, and verification requirements.

## M5 - Nexus-V Semantic Execution

Status: partial

Outcome: Plan requirements map to Nexus-V RTL/toolchain evidence and a
reproducible regression path.

Exit criteria:

- subsystem requirements trace to source and tests;
- NVASM/NVIR/NVOBJ regressions have expected outputs;
- simulator/toolchain prerequisites are reproducible;
- semantic state, audit, rollback, and Aegis invariants are exercised.

## M6 - OASIS Reality Compiler

Status: research

Outcome: a bounded sensing-to-environment pipeline turns calibrated observations
into an evidence-backed environment package and supports constrained inverse
design.

Exit criteria:

- observation, calibration, material-behavior, and environment schemas exist;
- one RGB/depth tabletop capture is reproducible;
- uncertainty and provenance survive compilation;
- an inverse-design candidate is validated against explicit constraints.

## M7 - Lightcore Research

Status: research

Outcome: Lightcore remains an evidence-gated physical execution profile beneath
Nexus-V, with software invariants preceding hardware claims.

Exit criteria:

- a software execution profile preserves Nexus-V semantics;
- a research evidence ledger separates measured, inferred, and hypothetical;
- one bounded optical/link experiment has calibration and failure criteria;
- no generated diagram is cited as physical proof.

## M8 - Operator Experience And Release

Status: planned

Outcome: humans can inspect, operate, recover, and contribute to Athena through
clear interfaces, GitHub planning, releases, and restoration drills.

Exit criteria:

- GitHub Project views represent backlog, roadmap, blocked, and active work;
- contributor templates and release checks are usable;
- an operator dashboard or report exposes current health and evidence posture;
- restore and handoff drills prove recoverability.
